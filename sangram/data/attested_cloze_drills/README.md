# Attested-sentence cloze drills — RQ2, cloze type

_Created: 25-09-2026 · Last updated: 25-09-2026_

Derived data asset behind the [cloze trainer](https://github.com/gasyoun/SanskritGrammar/blob/main/sangram/articles/attested-cloze-drills/index.mdx),
closing the third of [RQ2](https://github.com/gasyoun/SanskritGrammar/blob/main/DIGITAL_SANSKRIT_PEDAGOGY_FIELD_2026.md)'s
three named auto-drill shapes (sandhi-split · paradigm-fill · **cloze**). The
other two already shipped: sandhi-split as
[`build_emeneo_sandhi_drills.py`](https://github.com/gasyoun/SanskritGrammar/blob/main/scripts/build_emeneo_sandhi_drills.py),
paradigm-fill as the [attested-cell declension trainer](https://github.com/gasyoun/SanskritGrammar/blob/main/sangram/data/attested_drills/README.md)
(H1296, W2-add-a).

## Files

| File | What |
|---|---|
| [`build_attested_cloze_drills.py`](build_attested_cloze_drills.py) | the builder (scan + select + distractor lookup + emit) |
| [`attested_cloze_items.tsv`](attested_cloze_items.tsv) | the drill corpus — one row per cloze item (3000 rows) |

The widget payload (`src/components/talmud/attestedClozeData.js`) is generated by
the same script: up to 150 items per target part of speech.

## Why cloze needs no generation-vs-attested comparison

The declension trainer's answer key is *generated* (vidyut-prakriyā) and then
checked against the corpus; where they disagree, the row carries both sides and
a flag. A cloze item has nothing to generate: the blank is filled by the word
that is **actually in the sentence** at that position. The question and the
answer come from the same corpus attestation, so there is no `mismatch` case —
verification here is stronger, not weaker, than a generated key that might miss
a Vedic doublet.

Distractors are not invented either: they are other attested (cell,
`m_unsandhied`) forms of the same lemma, drawn from the same pinned snapshot,
excluding the target's own cell.

## `attested_cloze_items.tsv` schema

| Column | Meaning |
|---|---|
| `sentence_id` | DCS internal sentence id |
| `sent_id` | DCS's own citation id (`sentence.sent_id`) |
| `chapter_id` | DCS chapter id, for provenance |
| `n_tokens` | sentence length in tokens (4–12 by construction) |
| `target_idx` | 1-based word position of the blanked token |
| `lemma_id` / `lemma` | DCS lemma id / IAST citation form of the target |
| `upos` | `NOUN` or `VERB` |
| `cell` | `Case.Number` (NOUN) or `Tense.Mood.Person.Number.Voice` (VERB) |
| `formation` | raw `feat_formation` for VERB targets, unmodified — see "Perfect-default transparency" below; empty for NOUN |
| `form` | the attested, sandhi-affected surface form — the answer as it must fit the sentence |
| `unsandhied` | the attested unsandhied (citation-comparable) form |
| `corpus_freq` | target lemma's corpus-wide token count (any upos) — self-contained substitute for kosha `core_rank` |
| `sentence_cloze` | the sentence with the target replaced by `___` |
| `sentence_full` | the reference sentence, tokens joined in word order |
| `distractor_forms` | up to 3 other attested unsandhied forms of the same lemma, `\|`-separated |
| `n_distractors` | count of distractor forms found |
| `drill_mode` | `mcq` if ≥2 distractors, else `open` (free-text answer) |

## Perfect-default transparency (H3966)

DCS tags indicative Aorist and Perfect under one `feat_tense='Past'` value; the
split lives in `feat_formation` (a formation code — `root`/`them`/`s`/`is`/`red`/
`sa`/`sis` for the various Aorist stem types, `peri` for Periphrastic Perfect, or
**empty for the untagged simple-Perfect default** — see the
[CLAUDE.md traps section](https://github.com/gasyoun/SanskritGrammar/blob/main/CLAUDE.md)
and [H3966](https://github.com/gasyoun/Uprava/blob/main/handoffs/archive/H3966-Opus_SanskritGrammar_t2607-26-mood-guarded-rerun-v049_02.09.26.md)).
This builder never folds that into the `Past.Ind...` cell string silently: every
VERB row carries `formation` unmodified, so an empty value at `Past.Ind` is
visibly a default, never presented as independently confirmed.

## feat_voice discipline (VisualDCS `gen_paradigm_attested.py`, H1299 precedent)

DCS only distinguishes Passive from non-passive — it does not tag Parasmaipada
vs Ātmanepada separately. Voice is emitted as `NonPass`/`Pass`, never `Act`, so
no cell claims a P./A. split the corpus cannot support.

## Regenerate

```sh
python sangram/data/attested_cloze_drills/build_attested_cloze_drills.py
```

~25 seconds — this builder depends on nothing but the pinned VisualDCS DCS
snapshot (no kosha frequency file, no vidyut generation), unlike the declension
trainer's ~11-minute three-repo join.

| Input | Source |
|---|---|

## Limits

- **A sample, not a paradigm**: a distractor cell absent from the pool means "not
  attested in this snapshot", not "does not exist" — same caveat as the
  declension trainer.
- **Not kosha core**: lemma frequency here is the raw corpus-wide token count
  from the same DCS snapshot, not kosha's `core_rank` — comparable in spirit,
  not identical in value.
- **One target per sentence**: the FIRST eligible NOUN/VERB token by word order
  is picked, not the "best" one — deterministic and reproducible, at the cost of
  not exploiting every eligible word in a longer sentence.
- **100% MCQ in the current run** (`--min-lemma-freq 10` guarantees enough
  paradigm spread for ≥2 distractors in every sampled item) — `drill_mode=open`
  exists in the schema for a future lower-frequency pass, but is currently unused.
